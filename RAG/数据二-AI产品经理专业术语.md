# AI产品经理专业术语

1. **召回率 (Recall)**：指在所有确实为正样本的案例中，模型正确找出了多少；推荐应用场景是在涉及“宁可错杀不可放过”的内容审核或风险监控项目汇报中，用于强调模型对风险覆盖的全面性。
2. **准确率 (Precision)**：指在模型认为是正样本的案例中，有多少是真的正样本；推荐应用场景是在高价值客户精准推送或付费转化预测中，用于证明模型没有因为误扰而损害用户体验。
3. **F1-score**：是准确率和召回率的调和平均数，用于平衡二者；推荐应用场景是在需要综合评价模型稳定性、不希望任何一项指标有极端短板的业务评审中作为核心 KPI。
4. **AUC (Area Under Curve)**：衡量模型对正负样本排序能力的指标，数值越高代表排序越准；推荐应用场景是在个性化推荐或广告投放的算法调优中，展示模型对用户点击倾向的预判精度。
5. **NDCG (归一化折现增益)**：衡量搜索或推荐列表排序质量的指标，越相关的结果排在越前面得分越高；推荐应用场景是在搜索产品效果评估中，证明搜索结果的“首屏相关性”得到了显著提升。
6. **指标回测 (Backtesting)**：利用历史数据运行模型以验证其预测结果与真实发生情况是否一致的过程；推荐应用场景是在销量预测、股价分析等时序预测项目立项前，证明算法逻辑的可靠性。
7. **Ground Truth (真值/金标)**：指数据集中公认的标准答案或真实观测到的事实；推荐应用场景是在模型效果评测环节，强调评估是基于真实用户反馈或专家标注的高质量数据集。
8. **数据清洗 (Data Cleaning)**：去除原始数据中的噪声、错误、重复值和缺失值的过程；推荐应用场景是在项目复盘中，解释由于制定了更严格的清洗逻辑，使模型训练效率和精度得到了质的飞跃。
9. **特征工程 (Feature Engineering)**：从原始数据中提取对模型预测有用的变量或属性的过程；推荐应用场景是在策略调优阶段，通过引入用户行为、时间维度等新特征，解决模型“理解力”不足的问题。
10. **冷启动 (Cold Start)**：指系统缺乏新用户或新内容的历史行为数据，导致无法精准推荐的困境；推荐应用场景是在新业务上线初期，通过引入基于内容标签或热门召回的规则策略，平稳度过数据匮乏期。
11. **时延优化 (Latency Optimization)**：指降低从用户发送请求到收到回复之间的等待时间；推荐应用场景是在大模型对话产品中，通过流式输出、推理加速或缓存策略，提升用户的即时交互感。
12. **A/B 测试 (A/B Testing)**：通过实验组和对照组的流量对比，验证新算法或新策略有效性的科学方法；推荐应用场景是在版本迭代决策中，用严谨的统计学显著性差异证明新策略对业务指标的带动作用。
13. **MVP (最小可行产品)**：用最低成本和最快速度验证 AI 核心假设的原型；推荐应用场景是在探索新 AI 功能时，先通过调用第三方模型 API 跑通核心业务闭环，验证 PMF（产品市场契合度）后再投入自研。
14. **埋点 (Event Tracking)**：在产品中记录用户行为数据的技术手段，为模型提供训练标签和反馈；推荐应用场景是在构建数据闭环时，强调通过重新定义核心行为埋点，使模型获得了更精准的负反馈数据。
15. **转化漏斗 (Conversion Funnel)**：衡量从用户进入到最终达成业务目标的各个环节损耗；推荐应用场景是在业务分析中，找出 AI 赋能最关键的流失环节，并针对性地优化该步的算法干预。
16. **ROI (投资回报率)**：指 AI 带来的收益与算力、人力、Token 费用等投入的比值；推荐应用场景是在年度规划或立项评审中，向公司证明引入 AI 降本增效的经济价值和可持续性。
17. **Prompt Engineering (提示词工程)**：通过设计、优化指令，引导大模型输出更高质量结果的技术；推荐应用场景是在模型效果调优中，展示如何通过思维链或 Few-shot 技巧，将复杂任务的准确率从 70% 提升到 95%。
18. **幻觉治理 (Hallucination Governance)**：通过技术手段减少大模型产生事实错误或编造虚假信息的过程；推荐应用场景是在政务、医疗等严谨领域，展示如何通过 RAG 或自审计 Agent 确保 AI 输出的真实可靠。
19. **RAG (检索增强生成)**：结合外部私有知识库进行检索，再引导模型生成答案的技术架构；推荐应用场景是在企业知识库助手或个人智能助理项目中，解决模型知识过时和垂直领域深度不足的问题。
20. **微调 (Fine-tuning)**：在通用大模型基础上，使用垂直领域数据进行二次训练以提升专业性；推荐应用场景是在需要统一品牌语气或深度理解行业黑话的项目中，展示如何通过小规模数据实现模型的深度定制。
21. **Few-shot (少样本学习)**：在 Prompt 中给出少量范例让模型学习并模仿输出风格；推荐应用场景是在处理特定格式要求（如 STAR 故事撰写）时，通过给出 3 个金标案例，快速提升模型生成的规范性。
22. **CoT (思维链/Chain of Thought)**：引导模型写出中间推导步骤，从而提升其解决复杂逻辑问题的能力；推荐应用场景是在需要处理多步挖掘或数学计算的任务中，通过“Step by Step”指令显著减少逻辑跳跃带来的错误。
23. **SFT (有监督微调)**：利用“指令-回答”对进行微调，让模型学会遵循特定的指令格式；推荐应用场景是在打造垂直行业 Agent 时，通过 1000 条高质量标注指令，让模型真正具备“专家人设”。
24. **RLHF (强化学习从人类反馈中学习)**：通过人类对输出结果排序打分，让模型生成的语调更符合人类偏好；推荐应用场景是在打磨 AI 的情商和沟通风格时，通过引入专家评审机制，让 AI 说话更有温度、更专业。
25. **Temperature (采样温度)**：控制 AI 输出随机性的参数，值越高越有创意，值越低越稳定严谨；推荐应用场景是在设计写作助手（高温度）与逻辑解析工具（低温度）时，通过参数调优实现业务目标。
26. **上下文窗口 (Context Window)**：模型一次性能处理的 Token 数量限制，决定了它的“短期记忆”容量；推荐应用场景是在处理长文档摘要或超长多轮对话时，通过切片或摘要技术解决信息溢出和丢失问题。
27. **系统提示词 (System Prompt)**：预设在对话最前端的指令，定义 AI 的角色定位和行为准则；推荐应用场景是在多 Agent 系统中，为不同的 Agent（如挖掘官、撰写官）设定差异化的核心职能与禁令。
28. **Tokenization (分词)**：模型处理语言的基本单位，直接影响成本和理解精度；推荐应用场景是在成本优化专项中，通过精简 Prompt 的 Token 消耗，在不损失效果的前提下降低 30% 的 API 调用费。
29. **Function Calling (函数调用)**：模型自动判断并调用外部工具执行任务的能力；推荐应用场景是在构建闭环 Agent 时，让 AI 能够根据用户需求自动去查数据库、发邮件或运行代码。
30. **自我反思 (Self-Reflection)**：引导模型在生成结果后，对照约束条件进行自我检查和纠错；推荐应用场景是在自动化生成面试稿的项目中，让 AI 检查生成的 STAR 故事是否包含虚假数字，并自动打回修正。
31. **AI-as-a-Judge (以AI为裁判)**：利用高阶模型按照标准给其它模型的输出打分，实现自动化评测；推荐应用场景是在快速迭代 Prompt 期间，利用 GPT-4 实现分钟级的批量评测，极大提升开发效率。
32. **合成数据 (Synthetic Data)**：利用强模型生成模拟数据，用于训练弱模型或补齐稀缺场景；推荐应用场景是在真实失败案例数据极少的情况下，利用 AI 模拟生成带漏洞的项目描述，用于训练系统的纠错能力。
33. **多智能体编排 (Multi-Agent Orchestration)**：协调多个专门的 AI 角色按特定逻辑协作的过程；推荐应用场景是在解决复杂工作流（如从简历挖掘到 STAR 生成）时，通过逻辑编排让不同 Agent 各司其职，提升系统鲁棒性。
34. **长期记忆 (Long-term Memory)**：通过持久化存储历史交互，让 AI 能够跨越对话周期记住用户偏好；推荐应用场景是在个人求职顾问项目中，通过记住用户上一个项目的修改意见，提供连贯的咨询体验。
35. **向量数据库 (Vector Database)**：专门存储和检索高维向量数据的数据库，是 RAG 的核心底座；推荐应用场景是在构建企业级知识库时，强调通过优化向量检索算法，提升了语义匹配的召回率和速度。
36. **Zero-shot (零样本学习)**：指模型在不看任何范例的情况下，直接根据指令执行全新任务；推荐应用场景是在验证通用大模型基础能力或处理极度碎片化的简单任务时，展示模型的理解灵活性。
37. **嵌入 (Embeddings)**：将文本转化为数学向量的过程，代表了文本的语义特征；推荐应用场景是在做聚类分析或语义搜索时，解释如何通过更优秀的 Embedding 模型解决了“词不达意”的匹配问题。
38. **LoRA (低秩自适应微调)**：一种极低成本的模型微调技术，只更新一小部分参数；推荐应用场景是在资源有限、需要针对多个细分领域快速定制专属模型的创业项目中，作为技术降本增效的方案。
39. **语义相似度 (Semantic Similarity)**：计算两段文本在意思上的接近程度，而非字面匹配；推荐应用场景是在 FAQ 机器人优化中，通过语义相似度识别用户不同的问法，大幅降低了重复问题的配置工作量。
40. **重排 (Reranking)**：对 RAG 检索出来的多个结果进行二次精准排序的过程；推荐应用场景是在知识库助手回答质量差时，通过引入 Rerank 模型挑选出最精准的知识片段，显著减少模型被误导的概率。
41. **人机协同 (Human-in-the-loop)**：在 AI 处理过程中加入人工审核、标注或纠错的闭环；推荐应用场景是在涉及简历真实性等高敏场景时，通过 AI 初筛+人工确认的机制，确保最终交付物的严肃性。
42. **红队测试 (Red Teaming)**：模拟攻击者通过诱导提问来测试 AI 的安全边界和合规性；推荐应用场景是在产品上线前的安全评审中，展示通过红队测试修复了 AI 编造虚假身份信息或泄露企业隐私的漏洞。
43. **边缘AI (Edge/On-device AI)**：模型直接运行在用户设备端而非云端，兼顾隐私与速度；推荐应用场景是在处理个人简历等高度隐私数据时，通过端侧推理消除用户对信息泄露的担忧。
44. **多模态 (Multimodal)**：AI 同时处理文字、图片、音频、视频等多种信息的能力；推荐应用场景是在模拟面试产品中，通过多模态技术同时分析用户的回答逻辑、面部表情和语音语调，给出全方位的反馈。
45. **归因分析 (Root Cause Analysis)**：对 AI 表现差的原因进行拆解，分析是数据、模型还是 Prompt 出错；推荐应用场景是在处理 Bad Case 汇报时，清晰指出故障根源并给出针对性的修复计划。
46. **数据标注 (Data Annotation)**：人工为原始数据贴上标签或撰写标准答案的过程；推荐应用场景是在微调项目前，强调通过制定 12 维度的精细标注手册，为模型提供了高质量的学习样本。
47. **消融实验 (Ablation Study)**：通过移除系统中某个组件来验证其对整体效果贡献度的方法；推荐应用场景是在证明自研 RAG 模块的必要性时，用数据展示去掉该模块后，回答准确率直接下降了 40%。
48. **置信度 (Confidence Score)**：模型对自己给出答案的信心评分；推荐应用场景是在风控或医疗 AI 设计中，设定当置信度低于 0.7 时，系统必须转接人工或提示“仅供参考”，以防范误导风险。
49. **Token 成本控制 (Token Cost Optimization)**：通过精简、缓存或路由等手段降低 API 调用费用的策略；推荐应用场景是在高流量业务中，展示如何通过将简单请求路由给小模型，实现了 60% 的成本降低。
50. **鲁棒性 (Robustness)**：指 AI 系统在面对异常输入或攻击时仍能保持正常输出的能力；推荐应用场景是在系统测试阶段，通过输入各种极端情况（如故意写错、语序混乱）来验证系统是否依然能给出合理的逻辑引导。
